# بیلد بازتولیدپذیر (Reproducible Build)

هدف: از روی همان سورس و همان نسخهٔ ابزارها، همیشه دقیقاً همان APK ساخته شود
(همان هش SHA-256)، تا هر کسی بتواند مستقل بررسی کند APK منتشرشده واقعاً از همین کد ساخته شده است.

## چه چیزی پیاده شده است

- `gradle.properties`: `org.gradle.configuration-cache=true` — ورودی‌های بیلد قطعی‌تر و تکرارپذیرتر می‌شوند.
- `app/build.gradle.kts`: `dependenciesInfo { includeInApk = false }` — متادیتای امضاشدهٔ گوگل از APK حذف می‌شود (از قبل بود).
- در کد هیچ زمان‌سنجِ ساخت (build timestamp)، مسیر مطلق دستگاه سازنده یا مقدار تصادفی در APK گذاشته نمی‌شود.
- جاب CI در `.github/workflows/reproducible.yml`: در یک اجرا، APK نسخهٔ release را **دو بار** از صفر می‌سازد و هش SHA-256 هر دو را مقایسه می‌کند؛ اگر فرق داشته باشند جاب قرمز می‌شود.

## بررسی دستی

```sh
gradle :app:clean :app:assembleRelease
sha256sum app/build/outputs/apk/release/app-release.apk
gradle :app:clean :app:assembleRelease
sha256sum app/build/outputs/apk/release/app-release.apk
```

دو هش باید یکی باشند.

## محدودیت‌های صادقانه — بیت‌به‌بیت تضمین نمی‌شود

این جاب «تکرارپذیری در یک رانر» را بررسی می‌کند، نه «تکرارپذیری در هر ماشین و هر زمان» را:

- **نسخهٔ ابزارها:** نسخهٔ دیگری از JDK، گریدل، AGP یا R8 می‌تواند بایت خروجی را عوض کند (مثلاً نسخهٔ R8 در mapping و بهینه‌سازی DEX اثر می‌گذارد). بیلد فقط با نسخه‌های پین‌شده در CI (Java 17 Temurin، Gradle 8.10.2، AGP از `gradle/libs.versions.toml`) قابل‌مقایسه است.
- **ZIP و منابع:** AGP زمان فایل‌های داخل APK را نرمال می‌کند، ولی ترتیب یا محتوای `resources.arsc` و DEX می‌تواند با نسخهٔ aapt2/R8 عوض شود.
- **مسیر ساخت:** مسیر مطلق محل ساخت در APK گذاشته نمی‌شود، ولی بعضی متادیتای گریدل (نه APK) به آن وابسته است؛ مقایسه فقط روی فایل APK انجام می‌شود، نه کل پوشهٔ `build/`.
- **امضا:** APK نسخهٔ release در CI بدون امضا (unsigned) ساخته می‌شود؛ امضا با keystore مرحلهٔ جداگانه‌ای است و هش APK امضاشده با هش APK بدون امضا فرق دارد. جاب بازتولیدپذیری روی APK بدون امضا اجرا می‌شود تا امضا نتیجه را خراب نکند.

پس اگر جاب روزی قرمز شد، اول باید دید کدام ورودی عوض شده است (مثلاً ارتقای وابستگی یا نسخهٔ ابزار)، نه اینکه فوراً فرض شود کد دست‌کاری شده است. برای مقایسهٔ دقیق دو APK می‌توان از `unzip -l` و مقایسهٔ هش تک‌تک ورودی‌ها استفاده کرد.

## وضعیت

- جاب `reproducible.yml` در CI فعال است و روی هر push به شاخه‌های اصلی و هر Pull Request اجرا می‌شود.
- تاکنون هیچ مورد ناسازگاریِ بیت‌به‌بیت بین دو بیلد متوالی در یک رانر دیده نشده است؛ اگر دیده شود، همین سند به‌روز می‌شود.
